## 二、V2 阶段解决的五个关卡(按发现顺序)

### 1. os.sh 硬编码 aarch64 + brew update 的补丁抹除循环

`utils/os.sh` 的 OHOS 检测硬编码 `/lib/ld-musl-aarch64.so.1`,x86_64 上直接 `not support yet !!!` 退出。

**关键发现**:Harmonybrew 的 `brew update` 模型是 `git checkout --force -B stable refs/tags/7.0.6_3` —— **强制切到最新发布 tag**。任何对 `Library/**` 的本地修改(包括提交到 stable 分支的 commit,reflog 实证)都会在每次 update/auto-update 时被抹掉,而 update 中途 re-exec brew 时读到的就是被还原的 os.sh,形成"补丁→stash→还原→崩"的死循环。

**解法**:
- 补丁改为架构动态:`/lib/ld-musl-$(uname -m).so.1` + `HOMEBREW_PROCESSOR="$(uname -m)"`(归档 `v2/patches/os.sh-x86_64.patch`)
- 容器烘焙 `/etc/homebrew/brew.env`(Harmonybrew 官方 env 机制):`HOMEBREW_NO_AUTO_UPDATE=1` + `HOMEBREW_NO_INSTALL_FROM_API=1` + `HOMEBREW_OHOS_ALLOW_NO_TOOLCHAIN=1`
- `v2/apply-brew-patches.sh` 幂等应用全部补丁;stage-brew.sh 在组装时调用;**任何 brew update 后重跑一次即可恢复**

### 2. ruby 版本代沟:brew 要求 4.0.x

`utils/ruby.sh` 锁定 `HOMEBREW_REQUIRED_RUBY_VERSION="4.0"`,Linux 上允许 PATH 里的 system ruby,但必须 major.minor 精确匹配。V2 早前的 ruby 3.4.11 被拒。

**解法**:用 OHOS SDK 交叉编译 **Ruby 4.0.7**(与 brew 锁定的 portable-ruby 版本完全一致,装 `/opt/ruby40`)。两个坑:
- ruby 4.0 的构建要求更新的 baseruby,Ubuntu 22.04 的 ruby 3.0.2 被拒("executable host ruby is required")→ 先在 host 侧构建原生 ruby 4.0.7 作 baseruby(`v2/build-ruby40-host-then-cross.sh` 两步合一)
- **rbconfig 的 host_os 决定 ruby 侧 OHOS 身份**:交叉编译 host 三元组用 `x86_64-linux-musl`(config.sub 不认 ohos),运行时 `host_os=linux-musl` → brew ruby 侧 `OS.ohos?` 为假 → bottle_tag 落到 `x86_64_linux`(API URL 都错)。**解法:补丁 rbconfig.rb 的 `CONFIG["target_os"] = "linux-ohos"`**(host_os 运行时由 target_os 展开,`OS.linux?` 与 `OS.ohos?` 同时为真,与 Harmonybrew 语义一致)

### 3. ruby 侧三处 aarch64 硬编码(install 流程连环崩)

| 文件 | 问题 | 修复 |
|---|---|---|
| `os/linux/ld.rb` | x86_64 的 DYNAMIC_LINKERS 列表只有 glibc loader | 加 `/lib/ld-musl-x86_64.so.1` |
| `extend/os/linux/linkage_checker.rb` | SYSTEM_LIBRARY_ALLOWLIST 无 musl soname | 加 `ld-musl-x86_64.so.1` / `ld-musl-aarch64.so.1` / `libc.so` |
| `extend/os/linux/extend/ENV/super.rb` | `determine_dynamic_linker_path` 硬编码 aarch64 | 改 `RbConfig::CONFIG["host_cpu"]` 动态拼 |

以上与 development_tools 补丁合并归档为 `v2/patches/ruby-x86_64-ohos.patch`。

### 4. 编译工具链:OHOS SDK clang 是 glibc 的,进不了 musl 容器

无 bottle 可倒时 brew 要求 `DevelopmentTools.installed?` + `CompilerSelector` 找到真实 clang/gcc。OHOS SDK 的 llvm 全家是 **glibc 二进制**(ldd 实证依赖 `/lib64/ld-linux-x86-64.so.2`),在 musl rootfs 里无法运行。

**解法**:引入 **Alpine 的 musl 原生 clang15**(15.0.7,解释器路径与 OHOS 同为 `/lib/ld-musl-x86_64.so.1`)。`.apk` 即 gzip tar,解包后库进 `/lib`(排除 libz 避免与 rootfs 的 musl zlib 冲突),二进制在 `usr/lib/llvm15/bin`(`usr/bin/clang-15` 是相对符号链接,须一并拷贝)。`v2/install-alpine-clang.sh` 一键完成(10 个包:clang15、clang15-libs、llvm15-libs、libstdc++14、libgcc14、ncurses-libs、zstd-libs、libxml2、libffi、xz-libs)。

另:`development_tools.rb` 加 OHOS 分支 —— 显式环境变量 `HOMEBREW_OHOS_ALLOW_NO_TOOLCHAIN` 允许无工具链源码安装(脚本类 formula 不实际调编译器;真编译场景 V3 解决)。

### 5. Harmonybrew 强制 formula 必须在 tap 中

`brew install ./test.rb` 被拒("Homebrew requires formulae to be in a tap")。**解法**:`brew tap-new ohos/local` → formula 放入 `Library/Taps/ohos/homebrew-local/Formula/` → `brew install ohos/local/hello`。

## 三、已知边界(不阻塞 V2 结论)

1. **服务端无 x86_64_ohos 元数据**:`packages.x86_64_ohos.jws.json` 404 —— 这是 Harmonybrew 服务端/CI 的缺口(arm64 独享),恰是 V3 要做的"扩展 x86_64 构建矩阵"。开了 `HOMEBREW_NO_INSTALL_FROM_API`,search/info 走本地 tap 完全可用。
2. **brew update 无法一次跑绿**:API 下载 404 致 update 报错退出;且 tag 切换会抹 os.sh 补丁。容器默认禁 auto-update;显式 update 后跑 `apply-brew-patches.sh` 即恢复。根治 = 上游 PR(V3 计划)。
3. **Sandbox unavailable 警告**:OHOS 内核无 Landlock,brew 自动降级为无沙箱构建(仅警告)。
4. **ruby 缺 fiddle 扩展**(无 libffi):brew 不需要。
5. clang 的 target 三元组是 `x86_64-alpine-linux-musl`(通用 musl);面向 OHOS sysroot 的真实源码构建是 V3 的工具链课题。
