## 发现的 Bug(不影响容器路线,但 V1 需规避)

**OHOS musl x86_64 静态 libc 启动即段错误。** gdb 定位:`__init_libc+20` 处 `mov %fs:0x28,%rax`(栈保护读 TLS 金丝雀)时 FS 段基址尚未建立——x86_64 静态 libc 构建未加 `-fno-stack-protector`。strace 显示 execve 后零系统调用即 SIGSEGV,与内核无关(glibc 静态对照正常)。

- dockerharmony 容器路线全动态,不受影响
- **V1 从源码构建 musl 时,给 x86_64 静态库构建加 `-fno-stack-protector` 即可规避**(动态是否同样携带待 V1 实测;若同样有问题,修法一致)
